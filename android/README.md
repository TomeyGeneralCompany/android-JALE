# El Grande Mobile — Android

Android app shell for the existing All by Devoll Python desk, with a phone-private SQLite database. The desktop installation remains unchanged.

## Development build

Run GitHub Actions **El Grande Android APK** (or from the `android/` directory run `gradle :app:assembleDebug` with Java 17, Android SDK and Python 3.12 installed).

The workflow provides an APK artifact under its run's **Artifacts** section. Download it, then copy `app-debug.apk` to the company website and offer it as a direct download. Android users may need to permit installation from their browser. Keep the same application ID and signing key to support updates preserving phone-local data.

This uses Chaquopy to package Python, existing dashboard modules, and SQLite. It starts the desk on phone-only loopback, authenticates requests with a random in-memory session cookie, and displays it using Android WebView. Invoice PDFs are generated by Android's native PDF API and shared via the system share sheet. The phone does not rely on the desktop or on a hosted backend to manage local shop data.

## Signed website releases

Configure these four GitHub Actions secrets: `EL_GRANDE_KEYSTORE_BASE64` (base64 encoding of the JKS file), `EL_GRANDE_STORE_PASSWORD`, `EL_GRANDE_KEY_ALIAS`, and `EL_GRANDE_KEY_PASSWORD`. Keep the original JKS in a safe location; losing it prevents signing compatible future updates.

After validating the Android build, push a version tag such as `android-v0.14.0-1`. The `Publish signed El Grande Android APK` workflow publishes the APK as a GitHub Release asset. Your site can link directly to:

`https://github.com/TomeyGeneralCompany/android-JALE/releases/latest/download/el-grande-android.apk`

For repeatable downloads, versioned tag URLs are also available. Do not publish a debug APK as the production website installer.

## Important behavior

* **Local records:** Each Android installation has its own database in the app's private storage. It does not synchronize records with another phone or desktop. Removing app data or uninstalling it deletes local records: export them before doing so.
* **External integrations:** Gmail imports, Plaid, catalog feeds, and model-based estimate assistance depend on their own network services/configuration. The native WebView bridge and Android background lifecycle need device testing for each integration. No office computer is required for core job and ledger records.
* **APK signing:** Debug artifacts are for installation testing, not a production release/update channel. For production website distribution, configure a protected release signing key in GitHub secrets and publish a release-signed APK. Never commit the signing key or passwords.
* **Android testing:** Test job creation, changes, appointment saving, finalization, payment recording, invoice PDF sharing, SQLite persistence after force-close/reboot, and device rotation on a real Android phone before offering it to operators.

Source: the uploaded `el-grande-main.zip` was extracted into this independent Android repository. `integrations/all_by_devoll/` is a local copy of the desk source, while mobile-only startup lives in `android/app/src/main/python/mobile_server.py`.

Build validation is performed by the standalone repository's `El Grande Android APK` GitHub Actions workflow.

## Office automation

Open **Office automation** to load the Manistee County call list or paste your own lead CSV, assign follow-ups, and add signed service lines to a customer. Weekly, biweekly, and monthly stops appear in the existing calendar. Confirm measured snowfall by route to dispatch eligible snow stops. The app creates one draft per customer per completed service month and uses the existing invoice and payment ledger after approval. The revenue forecast opens to February 2027 and shows the following month alongside it.

One service line covers one property and a chosen service. Enter the agreed amount for any month the line overlaps. Snow lines require an end date. The desk catches up with scheduling and monthly drafts when it starts. Android needs the desk running for periodic Gmail intake and generation. Lead follow-ups and payment reminders are drafts for review.

To use one shared record between the office and the phone, run the desk from this revision on the office host and expose it through an authenticated HTTPS reverse proxy. Set `ABD_DASHBOARD_PASSWORD` to the operator password and `ABD_PUBLIC_ORIGIN` to the external HTTPS origin, and keep the desk listener on loopback when the proxy is on the same host. Open the hosted desk on the office computer. On Android, save the same origin in **Office automation → Shared office desk** and open the link in the phone browser. Use the hosted desk for shared entries. An existing phone database stays private to the phone, and its old records require a separate migration if they are needed on the host.

Complete a route stop by entering aggregate crew hours, the stop’s allocated miles, and disposal fees. The office can set default labor and mileage rates, and the saved stop keeps its own rates for historical reporting. **Route margins** shows monthly agreement charges, approved invoices, the 15% parent share, and recorded costs by route or customer. Completed stops from earlier versions remain visible as missing costs until their actuals are entered.

## Live call coach

On Android, open a lead in **Office automation** and select **Call with live coach**. Enter the provider’s secure WebSocket URL, SIP account, password, and outbound dial domain if it differs from the account domain. The provider must accept WebRTC calls over SIP WebSocket and support outbound phone calls for PSTN destinations. Use **Prepare English speech model** once to cache the on-device Moonshine Tiny Streaming model. After the call connects and the prospect agrees to live transcription, select **Start live coaching**. The suggested line comes from All by Devoll’s approved responses. Review the call notes before saving. Audio and unsaved transcript text are temporary. Android 8 or newer and an up-to-date System WebView are required for live coaching.

The APK build needs Node.js and npm to bundle the pinned MIT-licensed SIP.js dependency. The SIP.js license is in `android/call-coach/SIP-LICENSE.md`. Moonshine Voice 0.1.6 and the English Tiny Streaming model are MIT-licensed.
